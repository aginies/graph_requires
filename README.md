# Goal

Generate a **graph** of all packages that require any of the provides of a package for SUSE and openSUSE).
This use **zypper** with **--requires-pkg** option on current system, so its using the actual Repositories set on the system.
If you are using some extra repository this can report false result compare to an '''official''' installation.
To avoid any false result it is recommended to use the container way.

# SUSE SLES case

To be able to access all repositories you need an SCC credentials, and the container requires a writable file, and as use there is some limitation, so you need as root to change the ACL on the file:
```shell
setfacl -m u:aginies:r /etc/zypp/credentials.d/SCCcredentials
```

About SCC and credentials, look at the online documentation at https://scc.suse.com/docs/userguide

# Usage

First clone this repo:
```shell
git clone https://github.com/aginies/graph_requires.git
```

Switch the script to executable and use it on your system:
```shell
cd graph_requires
chmod 755 graph_requires.py
./graph_requires.py PACKAGE_NAME,PKG2,PKG3 [OPTIONS]
```

The package list is one comma-separated argument; the output directory is
an option (`-d`), not a positional argument.

Options (see also `./graph_requires.py --help`):

| Option | Description |
|--------|-------------|
| `-d, --dir DIR` | Output directory (default: `/tmp/graph`) |
| `--format {html,html3d,jpg,png,svg,pdf}` | Output format (default: `html`) |
| `--layout {dot,sfdp,fdp,twopi,circo}` | Graphviz layout engine (default: `dot`) |
| `--stagger N` | Stagger leaf nodes to reduce graph width (uses `unflatten -l N`, image formats only) |
| `--round2` | Also expand the reverse dependencies of the found packages (a second round) |

`html` produces an interactive 2D view (vis-network) and `html3d` an
interactive 3D view (3d-force-graph); both open in a browser and do not
need the Graphviz `dot` binary, but they load their JavaScript library
from the unpkg CDN, so viewing them requires internet access (see
#Limit). `jpg`, `png`, `svg` and `pdf` render a static image and require
Graphviz.

# Example

```shell
./graph_requires.py qemu
Analyzing reverse dependencies for: qemu
Finding packages requiring 'qemu'...

Total nodes found: 187
DOT file generated: /tmp/graph/qemu.dot
Interactive HTML view generated: /tmp/graph/qemu.html
```

Static image, with the second round expanded and a staggered layout:

```shell
./graph_requires.py qemu --format jpg --round2 --stagger 10
Analyzing reverse dependencies for: qemu
Finding packages requiring 'qemu'...
  Expanding 'libvirt-daemon' (Round 2)...
Total nodes found: 412
DOT file generated: /tmp/graph/qemu.dot
Applying unflatten (stagger: 10) to reduce width...
Graph image generated: /tmp/graph/qemu_15-SP6.jpg
```

# Container

This provide you a clean environement to check requires.

Build the container:
```shell
./graph-container-manage.sh build
1. openSUSE Leap 15.5
2. openSUSE Leap 15.6
3. openSUSE Leap 15.7
4. openSUSE Tumbleweed
5. SUSE SLES 15SP5
6. SUSE SLES 15SP6
7. SUSE SLES 15SP7
8. SUSE SLE 16

Enter your OS choice [1-8]: 2
STEP 1/23: FROM opensuse/leap:15.6
STEP 2/23: LABEL Description="Graph requires Container"
..............
```

Use it:
```shell
./graph-container-manage.sh run
./graph-container-manage.sh run
localhost/graph-sles15-sp6      latest      7f7bfcf697fc  3 seconds ago  223 MB
Enter the container ID: 7f7bfcf697fc
Enter the package name (separated by comma): qemu,libvirt
Analyzing reverse dependencies for: qemu, libvirt
Finding packages requiring 'qemu'...
Finding packages requiring 'libvirt'...

Total nodes found: 214
DOT file generated: /tmp/graph/qemu_libvirt.dot
Graph image generated: /tmp/graph/qemu_libvirt_15-SP6.jpg
Generating image /tmp/graph/qemu_libvirt_sles15-sp6.jpg locally
```

On SLES the image can not be generated inside the container, so the
management script renders the `.jpg` locally with `dot` afterwards (that
is why a `..._sles15-sp6.jpg` file appears next to the one generated by
the script itself).

# Limit

If you try to graph what requires glibc... don't expect any result soon,
this can be very slow to render, especially with `--round2` (each direct
dependency is expanded once; lookups are memoized so a package shared
between several roots is only queried once).

The `html` and `html3d` views load their JavaScript libraries
(vis-network, 3d-force-graph, three, three-spritetext) from the
[unpkg](https://unpkg.com) CDN at the moment the file is opened: viewing
them requires internet access, and the libraries are not version-pinned
or integrity-pinned, so rendering may change over time. The generated
HTML only embeds package names and DOT data from your local zypper.
